# План: исправление трат через версии

**Цель:** дать пользователю возможность исправить трату, сохраняя предыдущие версии append-only.

**Архитектура:** полные снимки в существующей таблице `expense`, стабильный ID и увеличивающаяся версия. API и расчёты используют только последнюю версию. Старые события сохраняют совместимость через event.version = 1; редактирование доступно только в событиях протокола 2, а ограничение входа касается только несовместимых mobile-клиентов.

**Стек:** PostgreSQL / TypeORM / NestJS, web, shared KMM / Room.

**RFC:** [ADR-0003](../../adr/0003-append-only-expense-corrections.md).

Backend реализован и проверяется по этому плану. Web, mobile и ограничение старых клиентов остаются отдельными этапами.

## 1. БД и миграция

- [x] Добавить `version: integer`; существующим строкам присвоить `1`.
- [x] Заменить первичный ключ `id` на `(id, version)`.
- [x] Добавить индекс `(eventId, id, version DESC)`.
- [x] Обновить TypeORM mapping и проверить ссылки, требующие уникальности одного `expense.id`.
- [x] Проверить сохранность ID, дат, сумм и существующих записей после миграции.

Исправление выполняет INSERT полного снимка с прежним `id` и следующей версией. Старые строки не обновляются и не удаляются. `createdAt` остаётся датой траты, если пользователь её явно не изменил; `updatedAt` новой строки — время исправления. Дополнительных полей `operationId` и `operationHash` нет.

## 2. Backend и V4 API трат

| Метод и путь                                             | Назначение              |
| -------------------------------------------------------- | ----------------------- |
| `POST /api/v4/user/event/:eventId/expenses`              | Последние версии трат   |
| `POST /api/v4/user/event/:eventId/expense`               | Создание, `version = 1` |
| `POST /api/v4/user/event/:eventId/expense/:id/revisions` | Исправление             |
| `POST /api/v4/user/event/:eventId/expense/:id/history`   | История версий          |

POST для чтения сохраняет текущий подход с PIN в теле запроса. Остальные API, включая V3 валют, не меняются. Ручек удаления и отмены нет.

- [x] Создание вставляет `version = 1`; ответ содержит `id`, `version` и полный снимок.
- [x] Все обычные чтения и расчёты выбирают только максимальную версию по каждому ID; история читается отдельно. Оставшиеся старые read-пути также не должны выдавать все версии как самостоятельные траты.
- [x] Исправление принимает PIN, `expectedVersion` и полный исправленный набор полей. В транзакции проверяет доступ/данные, блокирует изменение, сравнивает последнюю версию с ожидаемой и вставляет `version + 1`.
- [x] При несовпадении версии возвращать `409` с актуальной тратой; не перезаписывать конкурентное исправление.
- [x] Использовать существующий механизм `Idempotency-Key`: повтор в пределах срока хранения возвращает прежний результат. После истечения TTL прежний expectedVersion даёт конфликт, а клиент перечитывает серверное состояние; новую версию автоматически не создаёт.
- [x] Проверять принадлежность плательщика и участников событию. `eventId` и `expenseType` исправлением не меняются.
- [x] При изменении описания/плательщика сохранять подтверждённые exchanged amounts. При изменении сумм, долей, валюты или даты пересчитывать автоматический курс на дату траты либо применять явно переданные custom amounts; старые версии не пересчитывать.

## 4. Mobile

- [ ] Миграция Room добавляет локальное `version = 1`, сохраняя local IDs и clientCreateId.
- [ ] Pull обновляет известную трату при большей версии; меньшую игнорирует. Локальная БД служит изменяемой проекцией серверных версий.
- [ ] Offline-исправления хранить в отдельной очереди с payload, expectedVersion и устойчивым Idempotency-Key. При повторах сохранять прежний payload и ключ.
- [ ] Хранить ожидающий отправки черновик отдельно от подтверждённого серверного снимка, чтобы pull его не стирал.
- [ ] Для неподтверждённой сервером траты сначала завершать create, затем исправление. Не менять уже отправленный create под прежним ключом.
- [ ] Обрабатывать `409`, включая повтор после истечения TTL, перечитыванием актуальной траты с сохранением черновика для пользователя.
- [ ] Убрать текущую кнопку отмены. Существующие записи, созданные старой отменой, сохраняются без автоматического объединения.

Проверить возможность модалки обязательного обновления на уже выпущенных сборках: сервер не может добавить отсутствующий UI или запретить офлайн-чтение старой локальной БД.

Компенсаций и адаптера для старых приложений не делаем. При откате отключаем исправление, но сохраняем чтение последних версий: старый backend, выдающий всю историю как список трат, приведёт к двойному учёту.

## Совместимость событий — backend, 2026-10-25

- Добавлено поле event.version с DB/VO default 1; явное создание с 2 включает редактирование. Миграция сохраняет существующие события в режиме 1.
- Проверка mobile использует существующий User-Agent: начиная с CommonEx/11 поддерживаются версии событий 1 и 2; до релиза 11 — только 1. Web не блокируется.
- Проверка охватывает HTTP/gRPC пользовательские ручки; редактирование событий протокола 1 запрещено для всех клиентов.
