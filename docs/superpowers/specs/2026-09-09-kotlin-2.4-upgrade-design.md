# Kotlin 2.4 Upgrade Design

## Objective

Upgrade the Android/KMM project from Kotlin 2.3.21 to Kotlin 2.4.20, adopt the Kotlin 2.4 features that apply to this codebase, and leave every Kotlin compile task free of warnings in hand-written code and build scripts. The upgrade also fixes a pre-existing iOS test compilation error that CI does not catch.

## Scope

- Kotlin 2.3.21 to 2.4.20 in `android/gradle/shared.versions.toml` and `android/gradle/buildSrc.versions.toml`.
- KSP 2.3.11 to 2.3.12 in both catalogs (KSP 2.3.10 added the module-name fix required by Kotlin 2.4).
- Gradle 9.7.1, AGP 9.3.2, Compose Multiplatform 1.12.0, Room 2.8.4, and Wire 6.4.7 stay unchanged.
- Backend, web, and infra projects are untouched.

## Feature Adoption

Only stable language features and one beta build feature are adopted. The stdlib survey found no natural call sites for the new `isSorted*`, `allDistinct`, `allEqual`, or map fallback functions, so no code is rewritten to use them.

- **Context parameters are stable.** Remove `-Xcontext-parameters` from `android/app/build.gradle.kts` and `android/shared/integration/base/build.gradle.kts`. Every shared module can now use context parameters without a flag.
- **Explicit backing fields are stable.** Remove `-Xexplicit-backing-fields` from `android/app/build.gradle.kts`, `android/baselineprofile/build.gradle.kts`, `SharedLibraryPlugin.kt`, and `SharedKmmLibraryPlugin.kt`. The five existing `field = MutableStateFlow(...)` declarations keep working unchanged.
- **`kotlin.uuid.Uuid` is stable.** Remove `@OptIn(ExperimentalUuidApi::class)` from `IdempotencyClientIdStore.kt` and `ClientCreateId.kt`.
- **Incremental Native compilation (beta).** Add `kotlin.incremental.native=true` to `android/gradle.properties` so local iOS klib rebuilds are incremental.
- **Keep** `-Xreturn-value-checker=check` (still experimental) and `-Xexpect-actual-classes` (expect/actual classes still beta). Keep `extraWarnings.set(true)` everywhere it is set today.

## Warning Policy

The pre-upgrade baseline was captured with `--rerun-tasks` across all Kotlin compile tasks and saved as `/tmp/kotlin-warnings-before.log`. It contains:

- Zero warnings in hand-written Kotlin code.
- 466 `Redundant visibility modifier` and 28 `var can be val` warnings, all in generated sources (Compose resource generator, Room KSP output for iOS, Wire). These are explicitly left alone; no compiler diagnostics are disabled and explicit API mode is not enabled.
- 45 `KLIB resolver: The same 'unique_name=...' found in more than one library` warnings on iOS targets. These come from JetBrains' intentionally empty `org.jetbrains.androidx.*` and `org.jetbrains.compose.*-internal` redirect klibs coexisting with the real `androidx.*` klibs. The compiler-side fix (KT-61096) is open. These are explicitly left alone; no dependency replacement rules are added.
- Zero Gradle deprecation warnings under `--warning-mode all`.

After the upgrade, any new warning in hand-written code or build scripts is fixed at its cause, including warnings about compiler flags that Kotlin 2.4 reports as redundant. The post-upgrade warning set must be a subset of the baseline set once generated-source and KLIB-resolver lines are excluded.

## Bug Fix Included

`IdempotencyKeyGeneratorTest` in `shared:core:network` has a backtick test name containing a comma, which Kotlin/Native rejects, so `compileTestKotlinIosSimulatorArm64` fails today. The test is renamed to drop the comma. No other test name in the repository contains a character Kotlin/Native rejects.

## Validation

Run from `android/` with `--quiet`:

1. Every Kotlin compile task with `--rerun-tasks --continue`: `compileAndroidMain`, `compileAndroidHostTest`, `compileKotlinIosArm64`, `compileKotlinIosSimulatorArm64`, `compileTestKotlinIosSimulatorArm64`, `compileIosMainKotlinMetadata`, `compileCommonMainKotlinMetadata`, `:app:compileDebugKotlin`, `:app:compileReleaseKotlin`, `:app:compileAutotestAndroidTestKotlin`, `:app:compileAutotestUnitTestKotlin`, `:baselineprofile:compileNonMinifiedReleaseKotlin`. Exit code must be 0.
2. `testHostTest` and `:app:test` pass.
3. `:app:assembleDebug` and `:app:assembleRelease` succeed.
4. `--warning-mode all help` reports no Gradle deprecations.
5. Warning diff against the baseline log as described in the warning policy.

## Delivery

All changes land as a single commit on a feature branch off `main`. The pre-existing unrelated working-tree change to `android/gradlew.bat` and the untracked `.DS_Store` and `.idea/yatool.xml` files are not included.
